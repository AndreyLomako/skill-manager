# Skill Manager

Приложение для Windows, macOS и Linux, которое ставит скиллы Claude Code и Codex в ваши проекты.
Проекты подтягиваются сами — из VS Code, Claude Code и Codex. Вы отмечаете скиллы по категориям
и одной кнопкой ставите их в проект или глобально, для Claude, Codex или обоих.

## Установка

Все файлы — на странице [Releases](https://github.com/AndreyLomako/skill-manager/releases).
Node.js и браузер не нужны. Нужен Git в `PATH`: скиллы из репозиториев (в том числе impeccable,
который идёт по умолчанию) загружаются через него. Без Git остальной каталог работает,
а у таких скиллов будет значок `!` с причиной.

### Windows

1. Скачайте `Skill-Manager-Setup-<версия>.exe` и запустите.
   Права администратора не нужны: приложение ставится только для вас
   (в `%LOCALAPPDATA%\Programs\skill-manager`), ярлыки появляются на рабочем столе и в меню «Пуск».
2. Установщик пока не подписан, поэтому при первом запуске Windows SmartScreen покажет
   «Система Windows защитила ваш компьютер» — нажмите «Подробнее» → «Выполнить в любом случае».

### macOS

1. Скачайте файл `.dmg`, откройте его и перетащите «Skill Manager» в «Программы».
2. Приложение не подписано сертификатом Apple, поэтому первый запуск macOS заблокирует.
   Откройте «Системные настройки → Конфиденциальность и безопасность», найдите сообщение
   о Skill Manager и нажмите «Всё равно открыть», затем подтвердите запуск.
   Дальше приложение запускается как обычно.

Сборка — для Mac на Apple Silicon (M1 и новее).

### Linux

- **AppImage** (любой дистрибутив, обновляется сам): скачайте файл `.AppImage`, сделайте его
  исполняемым и запустите:

  ```sh
  chmod +x Skill*Manager*.AppImage
  ./Skill*Manager*.AppImage
  ```

  Если AppImage не запускается из-за FUSE — установите `libfuse2` (в Ubuntu 24.04 пакет `libfuse2t64`)
  или запустите с ключом `--appimage-extract-and-run`.
  В Ubuntu 23.10 и новее AppArmor может не дать AppImage запустить песочницу Electron
  (ошибка про `chrome-sandbox` / «SUID sandbox helper»). В таком случае поставьте `.deb` —
  у него песочница настраивается при установке.
- **.deb** (Debian, Ubuntu и производные):

  ```sh
  sudo apt install ./skill-manager_<версия>_amd64.deb
  ```

  Приложение появится в меню приложений (категория «Разработка»). Удаление — `sudo apt remove skill-manager`.

## Запуск и закрытие

- Повторный запуск не открывает второе окно, а показывает уже открытое.
- Закрытие окна полностью завершает приложение (на macOS тоже — в доке оно не остаётся).
- Удаление: Windows — «Параметры Windows → Приложения → Skill Manager»; macOS — перенесите
  «Skill Manager» из «Программ» в корзину; Linux — удалите файл `.AppImage` или `sudo apt remove skill-manager`.

## Обновления

Приложение проверяет новую версию через 10 секунд после запуска и затем каждые 6 часов.
Ошибки проверки (нет сети и т. п.) не показываются — они пишутся в `logs/updater.log` (см. «Где лежат данные»).

| Система | Как обновляется |
|---|---|
| Windows | Сама: новая версия скачивается в фоне, затем появляется «Загружена версия X. Перезапустить и обновить сейчас?». «Перезапустить» ставит её сразу, «Позже» — при следующем закрытии приложения. |
| Linux, AppImage | Так же, как на Windows: файл `.AppImage` заменяется новой версией. |
| macOS | Уведомлением: «Вышла версия X» → «Открыть страницу загрузки» открывает релиз, откуда нужно скачать и поставить новый `.dmg`. Самообновление на macOS требует подписи Apple, которой пока нет. |
| Linux, .deb | Уведомлением, как на macOS: скачайте новый `.deb` и установите его той же командой `sudo apt install ./…deb`. |

О каждой новой версии приложение спрашивает один раз за запуск.

## Где лежат данные

Папка данных `<данные>`:

| Система | `<данные>` |
|---|---|
| Windows | `%APPDATA%\Skill Manager` |
| macOS | `~/Library/Application Support/Skill Manager` |
| Linux | `~/.config/Skill Manager` |

| Что | Где |
|---|---|
| Мои скиллы, настройки | `<данные>/user/` |
| Корзина удалённых скиллов | `<данные>/user/trash/` |
| Клоны репозиториев со скиллами | `<данные>/cache/` |
| Журнал сервера (если приложение не запускается) | `<данные>/logs/server.log` |
| Журнал проверки обновлений | `<данные>/logs/updater.log` |
| Базовый каталог | идёт с приложением (`resources/catalog` внутри него), обновляется новой версией |

Удаление и переустановка приложения папку `<данные>` не трогают — ваши скиллы и настройки сохраняются.

## Каталог скиллов

### Категории

Вокруг круга — «Дизайн», «Видео», «Другие», «★ Мои скиллы» и «✓ Установлено».
У «Видео» есть подразделы «Монтаж» и «Генерация»: они появляются таблетками над списком,
а счётчик на «Видео» суммирует выбранное во всех подразделах. В «★ Мои скиллы» — только ваши
скиллы и плитка «Добавить скилл».

По умолчанию в «Дизайне» есть [impeccable](https://impeccable.style) — дизайн-директор для интерфейсов
(`/impeccable critique`, `audit`, `polish` и др.). Для Claude и Codex ставятся разные копии
из его репозитория, каждая под своего агента. Репозиторий загружается частично — только нужные папки;
при первом запуске карточка несколько секунд показывает «Загружается…».

### Карточки и подробности

На карточке — название, краткое описание и до трёх главных команд. Подробности (все главные команды
с пояснениями, для каких агентов есть версия, источник, ссылка «Подробнее ↗») открываются, если
задержать курсор на карточке, или по кнопке «i» / клавише `i` — тогда окно закрепляется и закрывается
по `Esc`, клику вне него или «×». Клик по команде копирует её.

### Паки

Пак — набор скиллов, который выбирается одним кликом. Маркер показывает, выбрано ли ничего (○), часть (◐)
или всё (◉); ✓ — всё уже установлено. «⌄» раскрывает список скиллов пака с флажками.
Каждый скилл пака ставится отдельной папкой, уже установленные пропускаются.

### Слои каталога

| Слой | Где | Кто меняет |
|---|---|---|
| Базовый | идёт с приложением | автор приложения, приходит с новой версией |
| Мой | `<данные>/user/user-catalog.json` | вы, через «★ Мои скиллы → Добавить скилл» |

Свой скилл с тем же `id`, что у базового, перекрывает базовый.

**Как удалить сломанный свой скилл:** закройте приложение, откройте `<данные>/user/user-catalog.json`
в редакторе, удалите запись скилла из `skills` (и, если он больше не нужен, его источник из `sources`),
сохраните файл и запустите приложение снова.
Формат файла — в [спецификации](docs/superpowers/specs/2026-10-18-skill-manager-mvp-design.md), раздел 4.

### Новые поля формата (v0.3.0)

Все поля необязательные, файлы старого формата остаются валидными (`"version": 1`).

| Поле | Что делает |
|---|---|
| `categories[].parent` | id категории верхнего уровня — делает категорию подразделом (вложенность одна) |
| `skills[].paths` | путь к скиллу в источнике отдельно для агентов: `{ "claude": "…", "codex": "…" }`. Указывается вместо `path`, не вместе с ним. Агент без пути этот скилл не ставит — в итогах будет «нет версии для Codex» |
| `skills[].summary` | краткое описание для карточки; если нет — берётся `description` |
| `skills[].commands` | главные команды `[{ "cmd": "/x run", "hint": "что делает" }]`, не больше 8 |
| `skills[].commandsMore` | сколько ещё команд есть («+N команд» в подробностях) |
| `skills[].homepage` | ссылка «Подробнее», только `https://` |
| `packs` | `[{ "id", "title", "category", "summary"?, "skills": [id…] }]` — скиллы пака объявляются в `skills` того же слоя, в категории пака; id пака не совпадает с id скилла |

Пример — базовый каталог [`catalog/catalog.json`](catalog/catalog.json).
Полное описание — в [спецификации каталога v2](docs/superpowers/specs/2026-10-19-skill-manager-catalog-v2-design.md), раздел 2.

## Агенты и области

Скиллы ставятся в одну из четырёх папок — в зависимости от области (проект или «🌐 Глобально»)
и агента, выбранного в нижней панели (Claude / Codex / Оба). `~` — домашняя папка
(`%USERPROFILE%` на Windows):

| Область | Агент | Папка |
|---|---|---|
| Проект | Claude | `<проект>/.claude/skills` |
| Проект | Codex | `<проект>/.agents/skills` |
| Глобально | Claude | `~/.claude/skills` |
| Глобально | Codex | `~/.agents/skills` |

Плитка «🌐 Глобально» ставит скиллы для всех проектов сразу и открывает «✓ Установлено».
Для Codex глобально там видны также скиллы из `~/.codex/skills` (старое место Codex): их можно
удалить в корзину и вернуть на то же место; новые скиллы ставятся в `~/.agents/skills`.
Если одно имя есть в обеих папках, показываются обе записи с подписью папки.

Скиллы подхватываются автоматически. Если папки со скиллами раньше не было —
выполните `/reload-skills` в Claude или перезапустите Codex.

### Категория «✓ Установлено»

Показывает всё, что лежит в папках выбранной области.

- Удалить (🗑) можно любую папку с `SKILL.md` в папке скиллов агента — не только
  скиллы, установленные приложением.
- Чужие скиллы собраны в свёрнутые группы, клик по заголовку раскрывает группу:
  - **«Плагин …»** — по группе на каждый плагин Claude Code. Кнопка «Удалить» удаляет плагин
    **целиком** (скиллы, команды, агенты, хуки) официальной командой `claude plugin uninstall`.
    Приложение само находит Claude Code — установленный как клиент (`claude` в `PATH`, `~/.local/bin`)
    или как расширение VS Code / Cursor / Windsurf. Если Claude Code не найден, приложение покажет
    команду `/plugin uninstall …` — её можно скопировать и выполнить в Claude Code. В корзину приложения
    плагин не попадает: вернуть его можно командой `/plugin install …`.
  - **«claude.ai»** (🔒) — скиллы, синхронизированные с вашего аккаунта claude.ai; отключаются на claude.ai.
  - **«Системные Codex»** (🔒) — идут с Codex.
- Устаревший скилл (↻) можно обновить до версии из каталога — только для того агента,
  к которому относится плитка.
- Скиллы из каталожного пака собраны под заголовком пака. «Весь пак» отправляет в корзину
  все его папки, а «Вернуть все» в уведомлении возвращает их. Скиллы пака можно удалять и по одному.

### Корзина

Удалённый скилл переносится в корзину приложения. Его можно вернуть кнопкой «Вернуть»
в уведомлении; записи старше 30 дней удаляются автоматически.
«Обновить» тоже не удаляет установленную копию безвозвратно: предыдущая версия уходит в корзину.

### Откуда берутся проекты

Только чтение — эти файлы приложение не изменяет:

- VS Code — `storage.json` в папке настроек VS Code:
  - Windows: `%APPDATA%\Code\User\globalStorage\storage.json`
  - macOS: `~/Library/Application Support/Code/User/globalStorage/storage.json`
  - Linux: `~/.config/Code/User/globalStorage/storage.json` (или `$XDG_CONFIG_HOME/Code/…`)
- Claude Code — `~/.claude/sessions` и `~/.claude.json`
- Codex — `~/.codex/state_*.sqlite`

## Известные ограничения

- **VS Code:** проект, закрытый в VS Code, остаётся отмеченным «открытым», пока VS Code
  не закрыт целиком — VS Code обновляет свой список окон только при открытии и выходе.
- **Без аппаратного ускорения графики** (виртуальные машины, удалённый рабочий стол) интерфейс
  работает медленно: анимированный круг заменяется статичным, но стеклянные эффекты остаются тяжёлыми.
- **Linux:** пути проектов сравниваются с учётом регистра (как в самой файловой системе);
  на Windows и macOS — без учёта.

## Для разработчиков

Нужны Windows, macOS или Linux, Node.js 24 или новее и git.

```sh
npm install
npm run electron:dev   # собрать и открыть приложение в Electron без установщика
npm run dist           # собрать установщик для текущей ОС в dist/
npm test               # тесты
```

- Сборка под конкретную ОС: `npm run dist:win` (NSIS-установщик), `npm run dist:mac` (dmg и zip,
  только на macOS), `npm run dist:linux` (AppImage и .deb, на Linux или в WSL). Рядом с установщиком
  появляются `latest*.yml` — по ним работают автообновления.
- При запуске из исходников данные лежат в папках репозитория `user/` и `.cache/` (обе в `.gitignore`,
  `git pull` их не трогает). Удаляя папку репозитория целиком, сохраните `user/`.
  Журналы — в `<данные>/logs/`, как у установленного приложения.
- `npm run dev` — сервер разработки на http://127.0.0.1:4317 для правки интерфейса в браузере
  с горячей перезагрузкой; установленное приложение использует порты от 4327, поэтому они не мешают друг другу.
- Распакованная сборка после `npm run dist` — `dist/win-unpacked`, `dist/mac-arm64`, `dist/linux-unpacked`.
- Обновления из исходников не проверяются. Проверить диалог «Вышла версия X» можно так:
  `SKILL_MANAGER_FAKE_VERSION=0.0.1 npm run electron:dev` (PowerShell:
  `$env:SKILL_MANAGER_FAKE_VERSION='0.0.1'; npm run electron:dev`) — приложение сочтёт себя версией 0.0.1
  и сравнит её с последним релизом.
- Иконка: исходник `build/icon.html`; после изменения выполните `node scripts/make-icon.mjs`
  (на Windows, нужен Microsoft Edge), чтобы пересобрать `build/icon.png` (из него же собираются
  иконки macOS и Linux) и `build/icon.ico`.
- **Если репозиторий лежит в OneDrive:** OneDrive синхронизирует `.cache/`, `.next/`, `dist/` и `node_modules/`
  и может временно блокировать файлы (ошибки `EPERM`/`EBUSY` при сборке). Исключите эти папки
  из синхронизации или держите репозиторий вне OneDrive.

### Как выпустить новую версию

```sh
npm version minor      # или patch: меняет версию в package.json, коммитит и ставит тег vX.Y.Z
git push --follow-tags
```

Тег `vX.Y.Z` запускает `.github/workflows/release.yml`. Сначала проверяется, что тег совпадает с версией
в `package.json`, и создаётся черновик релиза. Затем на Windows, macOS и Linux прогоняются типы и тесты,
собираются установщики, и `npm run release` выкладывает их вместе с `latest.yml`, `latest-mac.yml`
и `latest-linux.yml` в этот черновик. Он публикуется, только когда все три сборки прошли и все `latest*.yml`
на месте. Если одна сборка упала, черновик остаётся неопубликованным; после исправления перезапустите
упавшие задачи («Re-run failed jobs»). Пред-релизные теги (`v1.0.0-beta.1`) релиз не запускают.
Установленные копии увидят новую версию при следующей проверке. Каждый push в ветку и каждый pull request
проверяет `.github/workflows/ci.yml` (типы, тесты, сборка на трёх ОС).
