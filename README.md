# Skill Manager

Приложение для Windows, которое ставит скиллы Claude Code и Codex в ваши проекты. Проекты
подтягиваются сами — из VS Code, Claude Code и Codex. Вы отмечаете скиллы по категориям
и одной кнопкой ставите их в проект или глобально, для Claude, Codex или обоих.

## Установка

1. Скачайте `Skill-Manager-Setup-<версия>.exe` со страницы
   [Releases](https://github.com/AndreyLomako/skill-manager/releases) и запустите.
   Права администратора не нужны: приложение ставится только для вас
   (в `%LOCALAPPDATA%\Programs\skill-manager`), ярлыки появляются на рабочем столе и в меню «Пуск».
2. Установщик пока не подписан, поэтому при первом запуске Windows SmartScreen покажет
   «Система Windows защитила ваш компьютер» — нажмите «Подробнее» → «Выполнить в любом случае».

Node.js и браузер не нужны. Git в `PATH` нужен только для своих скиллов из репозиториев GitHub.

## Запуск и закрытие

- Запуск — ярлык «Skill Manager». Повторный запуск не открывает второе окно, а показывает уже открытое.
- Закрытие окна полностью завершает приложение.
- Удаление — «Параметры Windows → Приложения → Skill Manager».

## Где лежат данные

| Что | Где |
|---|---|
| Мои скиллы, настройки | `%APPDATA%\Skill Manager\user\` |
| Корзина удалённых скиллов | `%APPDATA%\Skill Manager\user\trash\` |
| Клоны репозиториев со скиллами | `%APPDATA%\Skill Manager\cache\` |
| Журнал (если приложение не запускается) | `%APPDATA%\Skill Manager\logs\server.log` |
| Базовый каталог | `<папка установки>\resources\catalog\` (обновляется новой версией) |

Удаление и переустановка приложения папку `%APPDATA%\Skill Manager` не трогают — ваши скиллы и настройки сохраняются.

## Каталог скиллов

| Слой | Где | Кто меняет |
|---|---|---|
| Базовый | идёт с приложением | автор приложения, приходит с новой версией |
| Мой | `%APPDATA%\Skill Manager\user\user-catalog.json` | вы, через «★ Мои скиллы → Добавить скилл» |

Свой скилл с тем же `id`, что у базового, перекрывает базовый.

**Как удалить сломанный свой скилл:** закройте приложение, откройте `%APPDATA%\Skill Manager\user\user-catalog.json`
в редакторе, удалите запись скилла из `skills` (и, если он больше не нужен, его источник из `sources`),
сохраните файл и запустите приложение снова.
Формат файла — в [спецификации](docs/superpowers/specs/2026-10-18-skill-manager-mvp-design.md), раздел 4.

## Агенты и области

Скиллы ставятся в одну из четырёх папок — в зависимости от области (проект или «🌐 Глобально»)
и агента, выбранного в нижней панели (Claude / Codex / Оба):

| Область | Агент | Папка |
|---|---|---|
| Проект | Claude | `<проект>\.claude\skills` |
| Проект | Codex | `<проект>\.agents\skills` |
| Глобально | Claude | `%USERPROFILE%\.claude\skills` |
| Глобально | Codex | `%USERPROFILE%\.agents\skills` |

Плитка «🌐 Глобально» ставит скиллы для всех проектов сразу.

Скиллы подхватываются автоматически. Если папки со скиллами раньше не было —
выполните `/reload-skills` в Claude или перезапустите Codex.

### Категория «✓ Установлено»

Показывает всё, что лежит в папках выбранной области.

- Удалить (🗑) можно любую папку с `SKILL.md` в папке скиллов агента — не только
  скиллы, установленные приложением.
- Только для просмотра (🔒): скиллы, синхронизированные с claude.ai, скиллы плагинов
  (управляются через `/plugin`) и системные скиллы Codex.
- Устаревший скилл (↻) можно обновить до версии из каталога — только для того агента,
  к которому относится плитка.

### Корзина

Удалённый скилл переносится в корзину приложения. Его можно вернуть кнопкой «Вернуть»
в уведомлении; записи старше 30 дней удаляются автоматически.
«Обновить» тоже не удаляет установленную копию безвозвратно: предыдущая версия уходит в корзину.

### Откуда берутся проекты

Только чтение — эти файлы приложение не изменяет:

- VS Code — `%APPDATA%\Code\User\globalStorage\storage.json`
- Claude Code — `%USERPROFILE%\.claude\sessions` и `%USERPROFILE%\.claude.json`
- Codex — `%USERPROFILE%\.codex\state_*.sqlite`

## Известные ограничения

- **VS Code:** проект, закрытый в VS Code, остаётся отмеченным «открытым», пока VS Code
  не закрыт целиком — VS Code обновляет свой список окон только при открытии и выходе.
- **Без аппаратного ускорения графики** (виртуальные машины, удалённый рабочий стол) интерфейс
  работает медленно: анимированный круг заменяется статичным, но стеклянные эффекты остаются тяжёлыми.
- Пока только Windows.

## Для разработчиков

Нужны Windows 10 или 11, Node.js 24 или новее и git.

```powershell
npm install
npm run electron:dev   # собрать и открыть приложение в Electron без установщика
npm run dist           # собрать установщик: dist\Skill Manager Setup <версия>.exe
npm test               # тесты
```

- При запуске из исходников данные лежат в папках репозитория `user/` и `.cache/` (обе в `.gitignore`,
  `git pull` их не трогает). Удаляя папку репозитория целиком, сохраните `user/`.
- `npm run dev` — сервер разработки на http://127.0.0.1:4317 для правки интерфейса в браузере
  с горячей перезагрузкой; установленное приложение использует порты от 4327, поэтому они не мешают друг другу.
- Распакованная сборка после `npm run dist` — `dist\win-unpacked\Skill Manager.exe`.
- Иконка: исходник `build/icon.html`; после изменения выполните `node scripts/make-icon.mjs`
  (нужен Microsoft Edge), чтобы пересобрать `build/icon.png` и `build/icon.ico`.
- **Если репозиторий лежит в OneDrive:** OneDrive синхронизирует `.cache/`, `.next/`, `dist/` и `node_modules/`
  и может временно блокировать файлы (ошибки `EPERM`/`EBUSY` при сборке). Исключите эти папки
  из синхронизации или держите репозиторий вне OneDrive.
