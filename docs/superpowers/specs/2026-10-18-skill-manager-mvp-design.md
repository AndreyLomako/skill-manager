# Skill Manager — MVP: дизайн

> Дата: 2026-10-18 · Эпик: `interface-n3i` · Исходное ТЗ: [ref/ref.md](../../../ref/ref.md)
> Этот документ уточняет ТЗ. Где они расходятся, действует этот документ.

## 1. Цель MVP

Рабочее окно, в котором можно:

1. увидеть проекты, открытые сейчас в VS Code (список обновляется сам);
2. выбрать проект;
3. отметить скиллы в одной или нескольких категориях;
4. нажать «Установить», чтобы скиллы скопировались в `<проект>/.claude/skills/<id>/`;
5. добавить свой скилл (ссылка на git-репозиторий или локальная папка + категория), который не пропадёт при обновлении базового каталога.

Интерфейс в стиле [ref/ref.png](../../../ref/ref.png): анимированный стеклянный круг, реагирующий на мышь, плитки категорий и скиллов.

### Не входит в MVP (следующие части)

- скиллы типа `plugin` и `command` (в MVP только `folder`);
- загрузка базового каталога из репозитория GitHub (в MVP базовый каталог — папка `catalog/` в этом репозитории, путь настраивается);
- журнал установок, наборы (пресеты), удаление через UI;
- история недавних проектов из самого VS Code (`state.vscdb`);
- упаковка в Electron / `.exe`.

## 2. Принятые решения

| Решение | Почему |
|---|---|
| **Next.js (App Router) + React + TypeScript** | Выбор пользователя |
| **Server Actions вместо HTTP API** | Компоненты вызывают серверные функции напрямую, отдельный API не пишется. Сервер работает только на `127.0.0.1` |
| **Окно:** `msedge --app=http://127.0.0.1:<порт>` | Окно без вкладок и адресной строки. Electron — позже |
| **Three.js (npm) для круга** | Выбор пользователя; ближе всего к референсу. Без `@react-three/fiber` |
| **Хранилище — JSON-файлы вместо PostgreSQL в Docker** | Приложение будут скачивать другие люди, а файлы работают без установки Docker. Базовый слой и так версионируется в git. Данных сотни записей |
| **Каталог из двух слоёв** (базовый + пользовательский) | Обновление базового слоя физически не может затронуть скиллы пользователя |
| **Правила `instruction_all/`** применяются по духу: BEM-подобные имена классов в CSS Modules, без CDN | Правила написаны для статичных HTML-сайтов, проект — React |
| **Vitest** для тестов | Быстрый, нативно работает с TypeScript |

│   │   ├── installer.ts         установка скилла, список установленных

│   │   └── actions.ts           'use server'
│   └── components/

│       ├── ProjectList/
│       ├── CategoryRing/
│       ├── SkillTiles/
│       ├── Cart/
│       └── AddSkillDialog/
├── catalog/
│   ├── catalog.json             базовый манифест

├── user/                        ← в .gitignore: всё пользовательское

│   ├── settings.json            недавние и вручную добавленные проекты

## 4. Каталог

### 4.1. Формат манифеста (общий для обоих слоёв)

```json
{
  "version": 1,
  "categories": [
    { "id": "design", "title": "Дизайн", "order": 1 }
  ],
  "sources": [
    { "id": "samples", "type": "local", "path": "./samples" },
    { "id": "some-repo", "type": "git", "url": "https://github.com/owner/repo", "ref": "main" }
  ],
  "skills": [
    { "id": "hello-skill", "source": "samples", "path": "hello-skill", "category": "design" }
  ]
}
```

- `sources[].type`: `local` (путь относительно файла манифеста или абсолютный) или `git` (URL GitHub и ветка/тег).
- `skills[].path` — путь к папке с `SKILL.md` внутри источника.
- Название и описание скилла берутся из frontmatter `SKILL.md` (`name`, `description`). Необязательные поля `title` / `description` в манифесте их переопределяют.

### 4.2. Слои

| Слой | Файл | Меняется |
|---|---|---|
| Базовый | `<baseCatalogDir>/catalog.json` (по умолчанию `./catalog`) | только автором приложения |
| Пользовательский | `user/user-catalog.json` (папка в `.gitignore`) | из интерфейса («Добавить скилл») |

`git pull` не трогает файлы из `.gitignore`, поэтому обновление приложения с GitHub не затрагивает `user/`. Риск — только удаление папки приложения целиком: в README — предупреждение сохранить `user/` при переустановке.

**Правила слияния:**

- категории: объединение по `id`, при совпадении побеждает пользовательская;
- источники: изолированы по слоям (внутренний ключ `base:<id>` / `user:<id>`), конфликтов нет;
- скиллы: объединение по `id`, пользовательский перекрывает базовый; у каждого скилла в результате есть `layer: "base" | "user"`.

Отсутствующий пользовательский файл означает пустой слой. Битый пользовательский файл не роняет приложение: показывается ошибка, базовый слой работает.

### 4.3. Git-источники

- Клонируются неглубоко (`git clone --depth 1 --branch <ref>`) в `.cache/<layer>-<id>/`.
- При первом запуске клонируются отсутствующие источники, по кнопке «Обновить каталог» выполняется `git pull` для всех.
- Ошибка клонирования помечает скиллы этого источника как недоступные (`error`), остальные работают.
- Используется системный `git` через `child_process.execFile` (без shell).

## 5. Проекты VS Code

- **Источник:** `%APPDATA%\Code\User\globalStorage\storage.json` → `windowsState`.
- **Берём:** `openedWindows[].folder` и `lastActiveWindow.folder`. URI `file:///c%3A/...` декодируется в путь Windows (`C:\...`), с корректной обработкой кириллицы и пробелов. Окна с `workspace` — папки из файла `.code-workspace`. Окна без папки пропускаются. Дубликаты убираются.
- **Активный проект по умолчанию:** `lastActiveWindow`.
- **Недавние:** проекты, которые приложение видело раньше (сохраняются в `user/settings.json`), плюс добавленные вручную.
- **Обновление:** клиент раз в 2 секунды вызывает server action `getProjects()`.
- **Риск:** скорость обновления `storage.json` при открытии и закрытии окон проверяется первой задачей плана. Если обновление запаздывает больше чем на несколько секунд, фиксируем ограничение, а мини-расширение VS Code берём в следующую часть.

## 6. Установка

`installSkills(projectPath, skillIds[], { overwrite })` возвращает результат по каждому скиллу: `installed` | `already-installed` | `error` (с сообщением).

- `projectPath` должен быть в списке известных проектов (открытые + недавние + ручные), иначе отказ.
- Целевая папка — строго `<projectPath>/.claude/skills/<skillId>/`. Проверяется, что итоговый путь не выходит за `<projectPath>/.claude/skills/` (защита от `..` в `id`).
- Если папка существует и `overwrite = false`, результат `already-installed`.
- Ошибка одного скилла не прерывает установку остальных.
- `getInstalled(projectPath)` возвращает имена папок в `<projectPath>/.claude/skills/`, содержащих `SKILL.md`, и для каждого скилла из каталога статус `up-to-date` | `outdated`.
- **Определение `outdated`:** хеш содержимого (SHA-256 по отсортированным относительным путям и байтам файлов) папки в каталоге ≠ хешу установленной копии. Дополнительных файлов-меток в проект не пишется. Обновление = `installSkills(..., { overwrite: true })` после подтверждения в UI.

## 7. Интерфейс

- **Фон:** градиент от тёмно-фиолетового к тёмно-синему, лёгкое зерно.
- **Круг (Three.js):** стеклянная капля с волнистым «дышащим» краем и переливом синий → фиолетовый → розовый по кромке. Смещается и наклоняется к курсору, край деформируется у курсора. Реакции: hover по плитке даёт пульсацию, выбор скилла — волну, успешная установка — вспышку, ошибка — красноватую рябь. При `prefers-reduced-motion` анимация упрощается.
- **Слева:** проекты (`●` открыт в VS Code, `○` недавний) и кнопка «Добавить папку».
- **Вокруг круга:** плитки категорий по дуге, на каждой бейдж с числом выбранных.
- **Внутри круга:** плитки скиллов категории: название, описание по hover, метки «✓ установлен» и бейдж «Мой» у скиллов пользовательского слоя (у базовых бейджа нет). При переполнении — прокрутка.
- **Снизу:** корзина (проект, количество по категориям, «Установить (N)»), раскрывается в список выбранного.
- **Диалог «Добавить скилл»:** URL репозитория или локальная папка, путь к скиллу внутри, категория (существующая или новая).
- **Всё — плитки, никаких «папок» и проводника.** Категории, скиллы, проекты и «Мои скиллы» — стеклянные плитки в стиле круга: полупрозрачные, с переливом кромки в цветах подсветки круга, анимированным появлением (каскадом), подсветкой при hover и «вдавливанием» при выборе.
- **Плитка-категория «Мои скиллы»** в кольце категорий показывает все скиллы пользовательского слоя (вне зависимости от их категории) и плитку «+ Добавить скилл».
- **Обновление установленного скилла:** если содержимое скилла в каталоге отличается от копии в проекте, на плитке значок «↻ обновить». Обновление = переустановка с подтверждением.
- **После установки:** подсказка перезапустить сессию Claude Code в проекте.
- Язык — русский.

## 8. Ошибки

| Ситуация | Поведение |
|---|---|
| Нет / битый `storage.json` | Список открытых пуст, сообщение; недавние и «Добавить папку» работают |
| Битый базовый манифест | Экран ошибки с текстом и путём к файлу |
| Битый пользовательский манифест | Ошибка-баннер, базовый слой работает |
| Git недоступен / клон не удался | Скиллы источника помечены недоступными |
| Ошибка копирования | `error` по скиллу, остальные продолжаются |

## 9. Тестирование

- **Vitest, `src/core`** — на временных папках (`fs.mkdtemp`):
  - разбор `storage.json`: папки, workspace, пустые окна, дубликаты, кириллица, `%20`, OneDrive-пути, отсутствующий/битый файл;
  - манифест: валидация, frontmatter, слияние слоёв и перекрытие;
  - установщик: копирование, `already-installed`, overwrite, защита пути, неизвестный проект, `up-to-date` / `outdated` по хешу;
  - корзина: добавить/убрать, счётчики по категориям, сохранение при переключении категорий.
- **Git-источники:** тест на локальном bare-репозитории (`git init --bare` во временной папке), без сети.
- **UI:** ручная проверка в окне + скриншот; Server Actions — тонкие обёртки над `core`, отдельно не тестируются.

## 10. Критерии приёмки

- [ ] Открытая в VS Code папка появляется в списке без перезапуска приложения не позже чем через 5 секунд (если проверка риска из п. 5 покажет, что VS Code пишет `storage.json` медленнее, фактическая задержка фиксируется в этом документе).
- [ ] Выбор 2 скиллов в одной категории и 2 в другой и «Установить» → 4 папки в `<проект>/.claude/skills/`, в UI ✓ по каждому.
- [ ] Повторный выбор проекта показывает эти скиллы как «установлен».
- [ ] Скилл, добавленный через «Добавить скилл», виден с меткой «Мой» и остаётся после замены `catalog/catalog.json` новой версией.
- [ ] Изменённый в каталоге скилл показывает «↻ обновить» в проекте, где стоит старая копия; после обновления значок пропадает.
- [ ] Круг анимирован, реагирует на мышь и действия; все элементы выбора — анимированные плитки.
- [ ] `npm test` проходит; `npm run build` без ошибок.
