# Skill Manager — каталог v2: Глобально, Дизайн/Видео/Другие, карточки с командами, паки

Дата: 2026-10-19 · Эпик beads: `interface-dcu` · Статус: согласовано с пользователем

## Зачем

Пользователь хочет видеть приложение как витрину своих инструментов. Для этого:

- «Глобально» показывает **все** глобальные скиллы Claude и Codex на компьютере. Их можно удалять, и туда же можно ставить новые.
- Категории отражают реальную работу: **Дизайн**, **Видео** (с подразделами **Монтаж** и **Генерация**), **Другие** (позже там будет «автопилот»), **Мои скиллы**.
- По каждому скиллу сразу видно, что он делает и какие у него главные команды.
- Большие наборы скиллов (будущий пак для монтажа) ставятся одним действием.
- Приложение готово к новому разделу «Шаблоны» с другой механикой.

## Решения пользователя

1. **Подробности скилла** — по наведению (~0,4 с) или по кнопке «ⓘ». Клик по карточке, как и раньше, выбирает скилл для установки.
2. **Паки** — одна карточка пака. Клик выбирает весь пак, «⌄» раскрывает список, где можно снять лишние скиллы.
3. **«Шаблоны»** пока не показываются, но место под раздел заложено в коде и разметке.

## Что меняется

### 1. Категории и навигация

- Вокруг орба: `Дизайн` · `Видео` · `Другие` · `★ Мои скиллы` · `✓ Установлено`. «Графика» переименована в «Дизайн» (id `design`).
- **Подкатегории.** У категории может быть `parent`. На кольце показываются только категории верхнего уровня. Если у выбранной категории есть дочерние, над сеткой внутри орба появляется ряд «таблеток» (`Монтаж` · `Генерация`); по умолчанию выбрана первая по `order`.
- Счётчик выбранных на «Видео» суммирует скиллы всех подкатегорий. Сводка в корзине пишет полный путь: «Видео › Монтаж 3».
- Пустая (под)категория показывает «Скоро здесь появятся скиллы».
- Четыре примера (`catalog/samples`) удаляются. «★ Мои скиллы» показывает только скиллы пользователя и плитку «Добавить скилл».

### 2. Формат каталога (`catalog/catalog.json`, `user-catalog.json`)

`"version": 1` остаётся. Все новые поля необязательные, поэтому старые файлы по-прежнему валидны.

```jsonc
{
  "version": 1,
  "categories": [
    { "id": "design", "title": "Дизайн", "order": 1 },
    { "id": "video", "title": "Видео", "order": 2 },
    { "id": "video-editing", "title": "Монтаж", "parent": "video", "order": 1 },
    { "id": "video-generation", "title": "Генерация", "parent": "video", "order": 2 },
    { "id": "other", "title": "Другие", "order": 3 }
  ],
  "sources": [
    { "id": "impeccable", "type": "git", "url": "https://github.com/pbakaus/impeccable.git" }
  ],
  "skills": [
    {
      "id": "impeccable",
      "source": "impeccable",
      "paths": { "claude": ".claude/skills/impeccable", "codex": ".agents/skills/impeccable" },
      "category": "design",
      "title": "Impeccable",
      "summary": "Дизайн-директор для интерфейсов: ревью UX, аудит доступности, шлифовка, типографика, цвет и анимации.",
      "commands": [
        { "cmd": "/impeccable critique", "hint": "UX-ревью с оценкой по эвристикам" },
        { "cmd": "/impeccable audit", "hint": "Доступность, скорость, адаптивность" },
        { "cmd": "/impeccable polish", "hint": "Финальная шлифовка перед релизом" },
        { "cmd": "/impeccable shape", "hint": "Продумать UX/UI до кода" },
        { "cmd": "/impeccable typeset", "hint": "Шрифты и типографическая иерархия" },
        { "cmd": "/impeccable animate", "hint": "Осмысленные анимации и микровзаимодействия" }
      ],
      "commandsMore": 18,
      "homepage": "https://impeccable.style"
    }
  ],
  "packs": [
    { "id": "video-editing-basic", "title": "Монтаж: базовый пак", "category": "video-editing",
      "summary": "…", "skills": ["cut-detect", "subtitles"] }
  ]
}
```

- **`category.parent`** — id категории верхнего уровня. Вложенность только одна; `parent` у дочерней с собственным `parent` — ошибка.
- **`skill.paths`** — путь отдельно для каждого агента (`claude`, `codex`). Это нужно, когда в репозитории разные копии для разных агентов, как у impeccable. Указывается либо `path` (общий для всех), либо `paths`, но не оба сразу. Агент, для которого пути нет, этот скилл поставить не может.
- **`skill.summary`** — одна-две строки по-русски, видны на карточке и в подробностях. Если `summary` нет, берётся `description` из манифеста, иначе из frontmatter.
- **`skill.commands`** — главные команды `{cmd, hint}`, не больше 8. На карточке показываются первые три. `commandsMore` — сколько ещё команд есть («+18 команд» в подробностях).
- **`skill.homepage`** — ссылка «Подробнее» (только `https://`, открывается в браузере).
- **`packs`** — пак: `{id, title, category, summary?, skills: [id…]}`. Скиллы пака объявляются в `skills` как обычно. id пака не должен совпадать с id скилла. Все скиллы пака должны существовать в том же слое и принадлежать категории пака.
- **Частичная загрузка git-источников.** Для git-источника загружаются только пути, на которые ссылаются его скиллы: `clone --depth 1 --filter=blob:none --sparse` + `sparse-checkout set --no-cone <пути>`. Обновление — `fetch --depth 1 --filter=blob:none` + `reset --hard FETCH_HEAD`, после него список путей переустанавливается. Репозиторий impeccable весит 81 МБ, а нужные папки — 2,2 МБ на агента. Если сервер не поддерживает фильтр, делается обычный поверхностный клон.

### 3. impeccable по умолчанию

- Источник — git `pbakaus/impeccable` (Apache-2.0), ветка по умолчанию.
- Claude ставит копию из `.claude/skills/impeccable`, Codex — из `.agents/skills/impeccable`. Внутри у копий разные пути к скриптам, поэтому подменять одну другой нельзя.
- Устанавливается в папку `impeccable`, то есть это обычная папка-скилл `/impeccable`.

### 4. Карточка скилла и подробности

- **Карточка:**
  - маркер выбора, название, строка `summary`;
  - ниже — до трёх «чипов» команд (`/impeccable critique` …);
  - справа — значки агентов: `C` (Claude), `X` (Codex), приглушённый, если для агента пути нет;
  - кнопка «ⓘ» в углу.
- **Подробности** (поповер рядом с карточкой, внутри орба):
  - название, `summary`;
  - полный список `commands` с пояснениями; клик по команде копирует её, появляется «Скопировано»;
  - «+N команд», если задан `commandsMore`;
  - доступно для: Claude / Codex;
  - источник (репозиторий или папка);
  - «Подробнее ↗», если есть `homepage`.
- **Как открываются подробности.** Наведение на 400 мс открывает поповер; уход курсора больше чем на 150 мс закрывает его, если поповер не закреплён. «ⓘ» и клавиша `i` на карточке в фокусе закрепляют поповер; закреплённый закрывается по `Esc`, клику вне него или «×».
- Ошибочные скиллы (`!`) открывают подробности с текстом ошибки.

### 5. Паки

- **В сетке.** Пак выглядит как карточка «Название · N скиллов». Скиллы пака отдельно в сетке не показываются.
  - Клик выбирает или снимает весь пак.
  - Маркер: ○ (ничего не выбрано), ◐ (выбрана часть), ◉ (выбрано всё), ✓ (всё установлено).
  - «⌄» раскрывает список скиллов пака с флажками. В раскрытом списке видно, какие скиллы уже установлены.
- **Установка.** Каждый скилл пака ставится отдельной папкой, как обычный скилл. Уже установленные пропускаются.
- **В «✓ Установлено».** Скиллы из каталожного пака сгруппированы под заголовком пака с кнопкой «Удалить весь пак»: все папки уходят в корзину. В уведомлении — «Вернуть все». Отдельные скиллы удаляются по одному, как раньше.
- Реальный пак для монтажа будет добавлен, когда пользователь пришлёт скиллы. Механика проверяется тестами на тестовом каталоге.

### 6. «Глобально»

- Клик по «Глобально» сразу открывает «✓ Установлено». Остальные категории доступны: установка в выбранном режиме идёт в глобальные папки.
- **Что показывается:**
  - Claude: `~/.claude/skills/*`, `synced`, плагины — как сейчас;
  - Codex: `~/.agents/skills/*` и **новое — `~/.codex/skills/*`**, а также `.system` из обеих папок, как сейчас.
- **Удаление** обычных скиллов из `~/.codex/skills` уходит в корзину, как из остальных папок. Для этого у `InstalledSkill` появляется поле `root` (папка, где найден скилл), а сервер проверяет, что `root` — одна из разрешённых для этой области и агента (`skillRoots(scope, agent, home)`). Восстановление из корзины возвращает скилл в ту же папку.
- Если одно имя есть и в `~/.agents/skills`, и в `~/.codex/skills`, показываются обе записи с подписью папки.
- **Установка** для Codex глобально по-прежнему идёт в `~/.agents/skills`; статус «установлен» учитывает обе папки.

### 7. Задел под «Шаблоны»

- `SkillManager.tsx` (518 строк) делится так:
  - `AppShell` — шапка с переключателем разделов, место под уведомления;
  - `SkillsSection` — всё, что сейчас относится к скиллам: проекты, орб, кольцо, сетка, корзина, диалоги.
- Разделы описаны списком `SECTIONS`. Переключатель «Скиллы | Шаблоны» появляется, только когда разделов больше одного; сейчас раздел один.
- Механика шаблонов — отдельная спецификация.

## Ошибки и крайние случаи

- **Нет git или сети при первом запуске.** У impeccable будет `!` «Источник недоступен: …», подробности покажут причину. Остальной каталог работает.
- **Скилл без пути для выбранного агента.** При режиме «Оба» скилл ставится только туда, где путь есть. В итогах появляется строка «Impeccable: нет версии для Codex», а не ошибка установки.
- **Пак, в котором часть скиллов с ошибкой.** Пак выбирает только доступные скиллы, а в раскрытом списке ошибочные помечены `!`.
- **Неверные `parent`, `packs` или одновременно `path` и `paths` в `user-catalog.json`.** Ошибка показывается как сейчас («Мой каталог: …»), базовый каталог работает.

- **Вживую:**
