## 1. Цель

Одно окно, в котором можно мышкой:

1. выбрать проект, открытый сейчас в VS Code (проекты подтягиваются автоматически);
2. открыть категорию скиллов («Графика», «Видео», «Документы»…) и отметить нужные;
3. перейти в другую категорию и отметить ещё;
4. нажать **«Установить»**, и все отмеченные скиллы поставятся в выбранный проект.

Больше не нужно искать команды установки и вписывать их в чат Claude Code для каждого проекта.

## 2. Термины

| Термин | Значение |
|---|---|
| **Скилл** | Папка с `SKILL.md` (и, возможно, вспомогательными файлами) для Claude Code |
| **Плагин** | Пакет Claude Code из маркетплейса (может содержать скиллы, агентов, хуки) |
| **Каталог** | Git-репозиторий на GitHub, где хранятся скиллы, разложенные по папкам-категориям |
| **Проект** | Папка, открытая в VS Code |
| **Набор (пресет)** | Сохранённая подборка скиллов, которая ставится одним кликом (например, «Лендинг») |

## 4. Определение открытых проектов VS Code

**Источник:** `%APPDATA%\Code\User\globalStorage\storage.json`, ключ `windowsState`:

- `openedWindows[].folder` — открытые окна с папкой (URI вида `file:///c%3A/Users/...`, нужно декодировать в путь Windows);
- `openedWindows[].workspace` — окна с multi-root workspace (`.code-workspace`): брать папки из файла workspace;
- окна без `folder`/`workspace` (пустые) пропускать;
- `lastActiveWindow` — использовать, чтобы предвыбрать проект, в котором вы работали последним.

**Поведение:**

- сервер следит за файлом (`fs.watch` + debounce) и пушит изменения в UI через SSE: открыли проект в VS Code — плитка проекта появилась в интерфейсе, закрыли — пропала (или ушла в «Недавние»);
- ниже открытых показывать **недавние проекты** (из истории VS Code), чтобы можно было поставить скиллы и в закрытый проект;
- ручное добавление папки (кнопка «Добавить папку…») как запасной вариант.

**Риск, который нужно проверить на этапе 1:** насколько быстро VS Code обновляет `storage.json` при открытии и закрытии окон. Если обновление запаздывает, запасной план — мини-расширение VS Code, которое при старте окна сообщает серверу `workspaceFolders` (POST на `127.0.0.1`).

## 5. Каталог скиллов

### 5.1. Структура репозитория `skills-library`

```
skills-library/
├── graphics/                 ← категория = папка
│   ├── _category.json        ← название, иконка, цвет, порядок
│   ├── frontend-design/
│   │   ├── SKILL.md
│   │   └── skill.json        ← метаданные для интерфейса
│   └── canvas-design/
├── video/
│   ├── remotion/
│   └── ffmpeg-tools/
├── documents/
└── presets/
    └── landing.json          ← набор: список id скиллов
```

### 5.2. Метаданные `skill.json`

```json
{
  "id": "remotion",
  "title": "Remotion",
  "description": "Создание видео на React",
  "icon": "video",
  "type": "folder",
  "install": null
}
```

| `type` | Как ставится | Поле `install` |
|---|---|---|
| `folder` | копирование папки скилла в `<проект>/.claude/skills/<id>/` | не нужно |
| `plugin` | установка плагина Claude Code с областью «проект» (запись в `<проект>/.claude/settings.json` или CLI `claude plugin install … --scope project`; точный синтаксис уточнить по актуальной документации Claude Code) | `{ "plugin": "name@marketplace", "marketplace": "<url>" }` |
| `command` | выполнение команды установки с рабочей папкой = папка проекта (например, `npx …`) | `{ "command": "npx …" }` |

Если `skill.json` нет, скилл считается типом `folder`, а название и описание берутся из frontmatter `SKILL.md`.

## 6. Установка и удаление

1. Пользователь выбирает проект и отмечает скиллы (в любом количестве категорий).
2. Нажимает «Установить (N)», и открывается окно подтверждения со списком того, что будет сделано (для `command` показывается точная команда).
3. Сервер выполняет установку **последовательно**, статус по каждому скиллу стримится в UI (ожидание → установка → ✓ / ✗ с текстом ошибки).
4. Результат записывается в журнал (БД).
5. После установки показывается подсказка: *«Перезапустите сессию Claude Code в этом проекте, чтобы скиллы подхватились»*.

**Дополнительно:**

- **Статус «уже установлено»:** при выборе проекта сервер сканирует `<проект>/.claude/skills/` и `.claude/settings.json`, установленные скиллы помечаются на плитках. Источник правды по установленному — сами файлы проекта, а не БД.
- **Удаление:** снять скилл с проекта (удалить папку или отключить плагин).
- **Обновление:** если версия в каталоге новее установленной (сравнение по хешу содержимого или коммиту), показывается значок «обновить».
- **Наборы:** установить пресет одним кликом, сохранить текущий выбор как новый пресет.
- **Область установки:** по умолчанию в проект. Опционально глобально в `~/.claude/skills/`.

**Безопасность:**

- сервер слушает только `127.0.0.1`;
- выполняются только команды, описанные в каталоге, произвольный ввод не принимается;
- запись идёт только внутрь `<проект>/.claude/` (для `command` — запуск в папке проекта);
- перед перезаписью существующей папки скилла спрашивается подтверждение.

## 7. Интерфейс

### 7.1. Стиль (по [ref.png](ref.png))

- **Фон:** тёмный градиент от глубокого фиолетового (слева снизу) к тёмно-синему (справа сверху), лёгкое зерно/шум.
- **Центральный объект:** полупрозрачный «стеклянный» круг-капля с волнистым краем; по контуру переливается подсветка синий → фиолетовый → розовый, блики на кромке.
- **Типографика и плитки:** светлый текст, плитки в стиле glassmorphism (полупрозрачные, `backdrop-filter: blur`, тонкая светлая обводка), акцентные цвета берутся из подсветки круга.

### 7.2. Поведение круга

- край постоянно и медленно «дышит» (волны по контуру);
- круг реагирует на мышь: слегка смещается и наклоняется в сторону курсора (параллакс), край деформируется ближе к курсору;
- реакция на действия: наведение на плитку даёт мягкую пульсацию, выбор скилла даёт волну по контуру, успешная установка даёт вспышку подсветки, ошибка даёт короткую красноватую рябь;
- реализация: WebGL-шейдер на чистом JS (без сторонних библиотек, чтобы не нарушать [01-libraries.md](../instruction_all/01-libraries.md)); fallback — canvas 2D / SVG;
- 60 fps на обычном ноутбуке; при `prefers-reduced-motion` анимация упрощается до статики с плавным hover.

### 7.3. Раскладка

```
┌──────────────────────────────────────────────────────────────────────┐
│  Skill Manager                                   [⟳ Обновить каталог]│
├───────────────┬──────────────────────────────────────────────────────┤
│ ПРОЕКТЫ       │                [Графика]   [Видео]                   │
│ ● interface   │        [Документы]  ╭──────────────╮  [Workflow]      │
│ ● kp          │                    ╱                ╲                 │
│               │     [Наборы]      │   ▢ remotion  ✓  │                │
│ НЕДАВНИЕ      │                   │   ▢ ffmpeg       │                │
│ ○ landing-x   │                   │   ▢ subtitles    │                │
│               │                    ╲                ╱                 │
│ [+ Папка]     │                     ╰──────────────╯                  │
├───────────────┴──────────────────────────────────────────────────────┤
│ Проект: interface · Выбрано: Графика 2, Видео 2   [ Установить (4) ] │
└──────────────────────────────────────────────────────────────────────┘
```

- **Слева:** список проектов. `●` — открыт в VS Code (живое обновление), `○` — недавний. Активный проект подсвечен.
- **Вокруг круга:** плитки категорий по дуге. Выбранная категория выделена, на плитке бейдж с числом выбранных в ней скиллов.
- **Внутри круга:** плитки скиллов выбранной категории (иконка, название, краткое описание по hover, отметка «✓ установлен»). Если скиллов много — прокрутка или пагинация внутри круга.
- **Снизу:** «корзина» выбора: проект, количество по категориям, кнопка «Установить (N)». Клик по корзине раскрывает список выбранного с возможностью снять отметку.
- Выбор сохраняется при переключении категорий.
- Язык интерфейса — русский.

## 8. База данных

**СУБД:** PostgreSQL в Docker (`docker-compose.yml` в репозитории приложения).

**Что хранится:**

| Таблица | Назначение |
|---|---|
| `projects` | известные проекты: путь, имя, дата последнего открытия, избранное |
| `catalog_index` | кэш индекса каталога (id, категория, тип, хеш версии) для быстрого поиска |
| `installations` | журнал: какой скилл, в какой проект, когда, какая версия, результат |
| `presets` | пользовательские наборы (если они не хранятся в каталоге) |
| `settings` | настройки приложения (путь к каталогу, порт, тема) |

### 8.1. Синхронизация БД (открытый вопрос — решить до этапа 3)

Требование: база должна быть «всегда одна» на всех машинах.

| Вариант | Как работает | Плюсы | Минусы |
|---|---|---|---|
| **A. Git — источник правды, БД — локальный кэш** *(рекомендуется)* | Всё, что должно быть общим (каталог, наборы, настройки), лежит файлами в `skills-library` на GitHub. Локальная БД в Docker строится из репозитория и хранит только машинно-зависимое (пути проектов, журнал) | Не нужен сервер; синхронизация уже есть через GitHub; БД можно пересоздать в любой момент | Журнал установок у каждой машины свой |
| **B. Центральная БД на сервере** | PostgreSQL в Docker на VPS, все машины подключаются к ней | Действительно одна база, общий журнал | Нужен сервер, доступ из сети, защита, работа офлайн невозможна |
| **C. Локальная БД + периодический экспорт в git** | Локальный Postgres, по кнопке/таймеру дамп (JSON) коммитится в репозиторий и подтягивается на других машинах | Без сервера, есть общий журнал | Возможны конфликты при одновременной работе с двух машин |

Рекомендация: **A**. Она закрывает «одну базу» через GitHub без отдельного сервера. Если позже понадобится общий журнал — добавить вариант C поверх A.

## 10. Нефункциональные требования

- Платформа: Windows 11 (основная). Пути, кодировки и запуск команд должны корректно работать с OneDrive-папками и кириллицей в путях.
- Запуск одной командой (`npm start` или ярлык), БД — `docker compose up -d`.
- Без интернета приложение работает с последней локальной копией каталога.
- Все операции с файлами проекта логируются; ошибки показываются в UI человеческим языком.
- Тесты: детектор проектов, парсер каталога и установщик покрываются автотестами (TDD).

## 13. Открытые вопросы

1. **Синхронизация БД:** подтвердить вариант A (или выбрать B/C) — раздел 8.1.
2. **Адреса репозиториев на GitHub:** имена `skill-manager` / `skills-library`, публичные или приватные; нужен ли токен доступа.
3. **Источники скиллов:** только свой каталог на GitHub или ещё и сторонние маркетплейсы плагинов Claude Code?
4. **Глобальная установка:** нужна ли опция ставить скилл не в проект, а глобально (`~/.claude/skills/`)?
5. **Другие редакторы:** учитывать ли VS Code Insiders / Cursor (у них свой `storage.json`)?
