# Стиль верстки и HTML

## BEM (модифицированный)

Модификатор — это **отдельный класс** с префиксом `_`, добавляется через пробел к основному классу.

```
.block               — блок
.block__element      — элемент (двойное подчёркивание)
._modifier           — модификатор (отдельный класс с одним подчёркиванием)
```

Примеры:
```html
<header class="header _is-show">
<div class="header__wrapper">
<ul class="header__list _margin">
<div class="catalog__item _is-hidden">
<button class="btn _is-active">
```

В CSS модификаторы описываем отдельными правилами:
```css
.header._is-show {
  display: block;
}

.header._header-fixed {
  position: fixed;
  top: 0;
}

.catalog__item._is-active {
  color: var(--color-primary);
}

.catalog__item._is-hidden {
  display: none;
}
```

**Не используем:**
- `--` для модификаторов (это не наш стиль)
- `block_modifier` слитно с блоком — модификатор всегда отдельным классом через пробел
- Глубокую вложенность: `.block__el1__el2__el3` — максимум 2 уровня

## Структура секции

Каждая секция на странице имеет одинаковую базовую конструкцию:

```html
<section class="about">
  <div class="container">
    <div class="about__wrapper">
      <!-- содержимое секции -->
    </div>
  </div>
</section>
```

- `section` — семантический тег секции
- `.container` — глобальный класс для ограничения ширины и горизонтальных отступов, не привязан к блоку
- `.about__wrapper` — внутренняя обёртка секции, именуется по БЭМ (не путать с глобальным `.wrapper` после `<body>`)

## Семантические теги

Используем семантику там, где она **реально несёт смысл**:

| Тег | Когда использовать |
|-----|-------------------|
| `<header>` | Шапка сайта |
| `<footer>` | Подвал сайта |
| `<main>` | Основной контент страницы |
| `<nav>` | Навигация (главная, хлебные крошки) |
| `<section>` | Смысловая секция страницы |
| `<ul>` / `<ol>` | Списки |
| `<h1>`–`<h3>` | Заголовки по иерархии |

**Теги, которые НЕ используем:**

```
<article>    — не используем
<aside>      — не используем
<figure>     — не используем
<figcaption> — не используем
<time>       — не используем
<address>    — не используем
<mark>       — не используем
<details>    — не используем
<summary>    — не используем
```

## Акцентирующие теги

```html
<!-- Используем только там, где реально нужно выделение -->
<strong>Важная информация</strong>   <!-- смысловой акцент -->
<b>Жирный текст</b>                  <!-- только визуальный — редко -->

<!-- НЕ оборачиваем всё подряд — только реальные случаи -->
```

## Навигация и ссылки

Во всех меню сайта в `href` прописываем **реальный путь к файлу** — это обеспечивает удобную навигацию и корректную работу ссылок:

```html
<!-- Хорошо -->
<nav class="header__nav">
  <a href="index.html">Главная</a>
  <a href="about.html">О нас</a>
  <a href="catalog.html">Каталог</a>
  <a href="contacts.html">Контакты</a>
</nav>

<!-- Плохо -->
<a href="#">О нас</a>
<a href="">Каталог</a>
```

## Телефоны и email

Все номера телефонов и адреса электронной почты оформляем как кликабельные ссылки с обязательными атрибутами `rel="nofollow"` и `target="_blank"`:

```html
<a href="tel:+74951234567" rel="nofollow" target="_blank">+7 (495) 123-45-67</a>
<a href="mailto:hello@example.com" rel="nofollow" target="_blank">hello@example.com</a>
```

## Внешние ссылки

Все ссылки на сторонние сайты содержат `rel="nofollow"` и `target="_blank"`. Для внутренних ссылок сайта эти атрибуты не используются:

```html
<!-- Внешняя ссылка -->
<a href="https://external-site.com" rel="nofollow" target="_blank">Текст ссылки</a>

<!-- Внутренняя ссылка — без атрибутов -->
<a href="about.html">О нас</a>
```

## Логотип

Логотип всегда оборачиваем в тег `<a>`:

```html
<a href="index.html" class="header__logo">
  <img src="img/logo.svg" alt="Название компании" />
</a>
```

## Общие правила

- Не используем inline-стили (`style=""`): все стили — в CSS-файлах. Исключение: сложная JS-логика или динамические анимации, которые нельзя реализовать через CSS-классы. **SVG-атрибуты** (`fill`, `stroke`, `width`, `height` и т.д.) не являются inline-стилями.
- `alt` у всех `<img>` — обязателен (см. [07-images.md](07-images.md))
- Не ставим `<div>` там, где подойдёт семантический тег
- Не ставим семантический тег там, где смысла нет — лишняя семантика хуже отсутствующей
- Классы именуем по БЭМ, ID не используем для стилизации
- Отступы в HTML — 2 пробела
