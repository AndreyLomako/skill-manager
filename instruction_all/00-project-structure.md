# Структура проекта (plain HTML/CSS/JS)

```
project/
├── index.html
├── about.html
├── catalog.html
├── [page-name].html
│
├── css/
│   ├── main.css
│   └── media.css
│
├── js/
│   └── main.js
│
├── img/
│   ├── main/
│   ├── header/
│   ├── footer/
│   ├── icon/
│   ├── form/
│   └── [page-name]/
│
├── font/
│   └── *.woff2
│
└── lib/
    ├── swiper-slider/
    │   ├── swiper-bundle.min.js
    │   └── swiper-bundle.min.css
    └── fancybox/
        ├── fancybox.umd.js
        └── fancybox.css
```

> Содержимое файлов описано в соответствующих инструкциях — [03-css.md](03-css.md), [04-javascript.md](04-javascript.md), [05-html-pages.md](05-html-pages.md).

## Правила соблюдения структуры (инструкция для AI-агента)

### Принцип «только нужное»

Папка создаётся **только если в ней будет реальный контент**. Пустые папки не создаются.

| Папка / файл | Создавать только если... |
|---|---|
| `lib/` | используется хотя бы одна библиотека |
| `lib/swiper-slider/` | используется Swiper |
| `lib/fancybox/` | используется Fancybox |
| `font/` | используются локальные шрифты |
| `img/[page-name]/` | есть изображения для этой страницы |
| `[page-name].html` | страница существует в проекте |

Все остальные папки и файлы из схемы выше — **создаются всегда**.

---

### Создание нового проекта

1. Сгенерировать полную структуру согласно схеме выше, применяя принцип «только нужное».
2. Создать стартовые файлы: `index.html`, `css/main.css`, `css/media.css`, `js/main.js`.
3. Не отступать от структуры без явного указания заказчика.

---

### Приведение существующего проекта к структуре

Если в проект помещены эти инструкции и поступает запрос привести проект к стандарту — агент обязан выполнить полную реструктуризацию:

1. **Анализ** — просмотреть все файлы и папки проекта, составить карту текущего расположения.

2. **Создание папок** — создать все недостающие директории согласно схеме (с учётом принципа «только нужное»).

3. **Перемещение файлов** — решение принимается по **типу файлов внутри папки**, а не по названию самой папки. Например: папка называется `styles/` — но внутри `.css`-файлы, значит это CSS и файлы переезжают в `css/`. Карта соответствий:
   - `.html`-файлы страниц → корень проекта
   - `.css`-файлы → `css/`
   - `.js`-файлы → `js/`
   - Изображения (`.jpg`, `.png`, `.webp`, `.svg` и т.п.) → `img/` с сортировкой по подпапкам (`main/`, `header/`, `footer/`, `icon/`, `form/`, `[page-name]/`)
   - Шрифты (`.woff2`, `.woff`, `.ttf`) → `font/`
   - Файлы библиотек → `lib/<название-библиотеки>/`

4. **Удаление старых папок** — после перемещения всех файлов исходная папка с нестандартным именем (например `styles/`, `javascripts/`, `scripts/`) удаляется, если она стала пустой.

5. **Нестандартные папки с контентом неизвестного типа** — папки с файлами, которые не попадают ни в одну из категорий выше (`video/`, `docs/`, `audio/`, `data/` и т.п.) — **не удалять и не перемещать**. Оставить на месте и продолжать ссылаться на них из кода по исходному пути.

6. **Переименование** — привести имена файлов в соответствие с [08-naming-conventions.md](08-naming-conventions.md).

7. **Проверка путей** — обновить все пути (`href`, `src`) в HTML и JS после перемещения файлов.
